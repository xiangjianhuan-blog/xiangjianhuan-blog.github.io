vibe coding：黄昏海岛2.0（Codex）

发表于2026-11-17|更新于2026-11-17
|字数总计:3.5k|阅读时长:11分钟|阅读量:

2026 年 11 月 · 单文件 Three.js 世界 · 11436 行 / 73 个模型 / 817 个碰撞体

1.0 是一座低矮岛，山腰到山顶只隔五米，走几步就到顶。2.0 把中央山脊抬到 43.7 米，山上长满混交林，树下有能真正挡住你的树干、石头和酒馆墙。

然后这次打开，海没了。

船浮在沙子上，海底裸露，地平线是一条干巴巴的土坡——不是”水变丑了”，是整片海没有被画出来。这篇先把这件事说清楚，再对照 1.0 那篇 讲明白 2.0 到底改了什么。

一、海是怎么消失的

现象很干净：地面在、树在、船在、天空在，唯独没有水面。船像搁浅在沙丘上，海底的沙纹直接暴露在空气里。

按 1.0 学到的第一条规矩，先看控制台，别急着动场景代码：

翻译一下：海面的片元着色器里，有一处 discard 分支用到了三个 uniform——船体深度预 pass 的采样器、它的分辨率倒数、以及开关。JS 侧的 oceanMat.uniforms 里这三个都注册了，值也每帧在更新；顶点着色器里也算好了 vShipClip。唯独片元着色器顶部忘了写 uniform sampler2D uShipDepth; 这一行。

GLSL 不认识这个名字，整个 fragment shader 编译失败，于是整个 oceanMat 作废。材质失效的后果不是”某块颜色不对”，而是这个 mesh 干脆不被提交绘制。

这是最贵的一条
着色器编译失败 = 整个材质消失，不是局部的像素错误。所以”某个物体整体不见了”时，第一反应应该是”它的材质编译过了吗”，而不是”它是不是没生成”。1.0 里已经踩过一次同样的坑（那次是 uUnder / uNight / uFlash），2.0 又踩了一次——因为这次加的 uniform 是在另一个着色器阶段里用的。

二、2.0 到底改了什么

先给一张总表，都是可以数出来的东西：

下面四件事，是我认为 2.0 真正的分水岭。

1. 岛长高了一倍多

1.0 的岛是”一个 S 曲线 + 一点噪声”，坡缓、顶低，站在岛中央能看见四周的海。2.0 在中央立了一道山脊，实测采样最高 43.7 m，两侧各接一段错位的山肩——错位是关键，正对着叠会像梯田，错开半拍才像被水冲出来的岩层。

山高了以后，植被不能再用一套规则撒。2.0 按高度带重新分层：

  • 峰顶与陡坡：混交林，密度最高，树冠互相咬合
  • 山肩台地：疏林 + 灌木，留出可以走的土路
  • 低地：仍是 1.0 的沙滩棕榈、野花、裸岩，但加了”高山林下色”——高处的草偏深、偏冷，低处偏黄绿

代价也很直接：山变陡，玩家会顺着坡滑下去，于是必须给”地形”本身一份坡度反馈，否则走山路像在冰面上。

2. 从”不能穿模”到”能站上去”

1.0 的碰撞基本是二维的：一个圆挡在树的位置，玩家绕开就行。问题有三个——箱子挡不住人、人上不了箱顶、树只有一根柱子粗。

2.0 把岛上所有实心东西都登记成带高度的体积体：树、岩石、酒馆、洞穴、码头用圆柱，木桶和木箱用可以旋转的盒子，一共 817 个。查询走 8 米的空间哈希格，只算玩家身边那一格。

改完之后多了三个 1.0 没有的手感：

  • 沿障碍滑动：撞到树干不会卡死，速度会投影到切线方向，贴着树滑过去
  • 箱顶是落脚面：跳上木箱能站住，站在箱顶能看见码头的另一侧
  • 跳得够高就能越过：脚底高于碰撞体顶部时，碰撞直接不生效——不是”永远挡着”

这条其实是”3D 游戏该有的样子”和”网页 demo”的分界线。前者的判定条件是高度，后者只有距离。

3. 船会真的晃了

1.0 的船是把位置和旋转直接写进去的：采样几个波高，算一个平均起伏，然后 ship.position.y = ...。船永远”配合”海，但从物理上说它是假的——你站在甲板上，脚下那块地板和浪没有关系。

2.0 换成 Rapier 动态刚体：24 个基础形状拼出船壳与甲板，21 个采样点分布在船底，每帧把每个采样点所在位置的水面高度换算成浮力与阻尼，交给刚体求解器算。船的横摇、纵摇、起伏，是解出来的，不是摆出来的。

代价是必须处理好两套坐标：模型船的船首朝 +X，航行逻辑朝 +Z；GLB 把甲板上的绞盘、栏杆全合并进船壳网格，想转动绞盘就不能拆件，只能在顶点着色器里按顶点位置圈出一块，绕自己的轴转。这些都不是”写个功能”，是”和一份别人做的模型对齐”。

顺带一提，船和水的交界处现在会做一次深度预 pass：站在船里往外看，浪顶不会穿过甲板糊在脸上，被船壳挡住的浪片元直接丢弃——也就是开头那三个漏声明的 uniform 干的事。

4. 有人气了

1.0 的岛很安静，海是海，风是风，但没有生物。2.0 加了 18 只海鸥：独立节拍振翅、滑翔时收翅、转弯时压坡、掠过水面会拉高。全部用 InstancedMesh 分批，一只鸟六个部件（躯干、头、翼×2、尾、喙），仍然只有 6 个 draw call。

声音也补了一层。1.0 有海浪、风、雨、雷和四首程序化曲子；2.0 加了海鸥叫、林鸟、夜间虫鸣，以及按材质切换的脚步声——沙滩是闷的、湿沙更闷、草地有细碎的高频、木栈桥有低频的”咚”、岩面偏硬。全部由 WebAudio 实时合成，没有多一个音频文件。

5. 水下：从”滤镜”到”折射”

这是 1.0 之后继续加的一层（代码里标着 2.1）。1.0 的水下是四件套：斯涅尔窗、焦散、悬浮颗粒、UV 波动的折射后处理。2.0 换成屏幕空间折射——把”没有水面”的场景先渲到一张半分辨率的 RenderTarget，水面在片元里按法线偏移去采样它：

  • 1 米内能看清水底的沙纹、海草、珊瑚
  • 4.6 米处透见度归零，只剩水色
  • 水下、远海、低画质档自动关闭，省掉一半渲染量

同时把”玩家踩的地面”从解析高度换成了渲染网格的插值高度（groundVisualHeight）：模型贴地、玩家行走、接触阴影三者用同一份高度，脚才不会陷进坡里半厘米。

三、哪些只是变大，哪些是换了做法

回头看 1.0 那篇的八条结论，2.0 其实只证实了一半，另一半被推翻了。

只是变大：行数从 6710 到 11436；树从十几棵到 616 棵；模型 69 到 73。这些是量的堆叠，方法没变。

换了做法（这才是 2.0 的价值）：

问题 1.0 的做法 2.0 的做法
玩家和障碍的关系 二维圆，只挡距离 三维体积，判高度：能滑、能站、能越
船和浪的关系 采样后直接写 transform 浮力采样喂给刚体求解器
玩家和地面的关系 解析地形函数 渲染网格插值（看到的才是踩到的）
浅水看不看得见底 后处理滤镜 屏幕空间折射抓帧
岛的天际线 单峰 + 噪声 山脊 + 两段错位山肩 + 林下分层

完全没变：9 个昼夜关键帧、6 种天气乘子、程序化海水与天空、CC0 资产路线、单文件交付、start.bat 零依赖启动。这几件事 1.0 就做对了，2.0 一行没动。

四、这次的三个坑

1. 着色器少一个声明，整片海消失

上面说过了。补一句可复用的检查法：改着色器时，新增的 uniform 要在每一个用到它的阶段都声明一遍。顶点着色器声明了不代表片元着色器能用，oceanMat.uniforms 里有不代表 GLSL 里有。

2. 帧率相关的过渡，在低端设备上会变慢

截图验收时遇到一个很怪的现象：切到”暴风雨”，等了十几秒，雨在下、浪在涨，但天还是黄昏的晴空。

原因是天气插值写成了 cur += (target - cur) * dt * 0.45。在正常帧率（60 fps）下，大约 2 秒收敛；但无头浏览器跑软件渲染只有个位数帧率，dt 被 Math.min(dt, 0.05) 钳住，一秒钟只推进几帧，同一个”2 秒过渡”被拉成了几分钟。

真正的教训不是”截图脚本要绕开它”（我确实改成截图前直接把 WEATHER.cur 置为终值），而是：所有 dt * k 形式的插值，都在暗中假设帧率。手机、集显、后台标签页都会让这个假设失效。要么用固定时间步累积，要么接受”过渡时间随帧率浮动”并写进注释。

3. 发布前要专门检查”默认值”

  • shipColliderDebug: true → 一进游戏全是青色线框
  • 调试用的 #perfInfo 面板、V／B 快捷键 → 留着可以，但不能默认开

默认值是写给自己看的，发布是给别人用的。这两件事必须分开过一次。

前面那篇 1.0 是 WorkBuddy 做的，这次是 Codex。工具换了，方法没换：把”我觉得不对”翻译成一句能执行、也能验收的描述。

“海不见了”是一句现象。翻译成”打开控制台，看 Shader Error，检查新增 uniform 在片元阶段的声明”之后，它才变成一个五分钟能关掉的 bug。而”岛应该更有分量”这种判断，最后落地成的是”山脊 43.7 米、两段错位山肩、817 个碰撞体”——只有这样，它才可能被实现，也才可能被验证。
