vibe coding：Threejs-Water-Package2.0（Claude）

发表于2026-11-24|更新于2026-11-24
|字数总计:2.6k|阅读时长:9分钟|阅读量:

2026 年 11 月 · 用 Claude 迭代的第二版 · 从「能看出风和光」磨到「能走上去的海岸」

1.0 讲的是怎么把一片海做出来：三段级联 FFT、峰顶白沫、各向异性波光、HDRI、水下光柱。2.0 改的不是这些参数，而是底层：水面整套换成 Ultra-Water 移植的四层级联 FFT，海岸从一块固定的潟湖岛变成五类可切换的网格地形，光照收成一份 SkyPreset，船体的起伏也从固定弹簧改成质量驱动。

想先看 1.0 的话：**vibe coding：Threejs-Water-Package1.0（WorkBuddy）**

🌊 打开 2.0 全屏在线 Demo →  原来的 1.0 在线体验已被这版覆盖，同一路径直接打开新版本

先看效果。下面这片海就是 2.0，鼠标可以直接转视角、开船、潜水；面板在右上角，左上角是操作提示：

想全屏看就点面板里的「全屏浏览」——iframe 没给 allow="fullscreen" 的话浏览器会拦掉。

一、效果上，和 1.0 差在哪

1. 浪从「三段」变成「四层」

1.0 是 600 / 85 / 12 m 三段级联、128² 的 FFT。2.0 换成 Ultra-Water 的 600 / 85 / 12 / 2.1 m 四层，256²，MRT 同时输出位移、坡度与二阶矩；最细那层 2.1 m 专门补近处的碎浪。实际观感是：同样的风速下，浪面多了一层细碎起伏，远处的长浪和近处的碎浪能同时看清，不再是「一张放大的法线图」。

风暴：风 30 m/s、波长 70 m。2.0 白沫不再按「高度过阈值」生成，而是跟局部面积比（Jacobian）和坡度方差走，浪越挤越容易起沫，所以大浪时的白沫是成片堆在破碎带上，而不是均匀撒满。

日落：低太阳角，暖色晚霞。2.0 把天空、雾色、环境光、曝光全部收进一份 SkyPreset，换预设计算的是一套配方，不再是几个滑块各自为政。

月光：星空 HDRI，曝光压到 4.2。水面反射直接从同一张 HDRI 烘出的立方体里取，不会出现「背景是夜空、反射还是白天」的穿帮。

2. 从「一座潟湖岛」到「五类海岸」

1.0 只有一块固定的岛。2.0 加了 terrain：平缓沙滩 / 珊瑚礁台 / 悬崖海岸 / 环礁潟湖 / 开阔海，切换会重建网格地形、岸线贴图和岸滩撒点，并把船停到合适位置。

从左到右、从上到下：平缓沙滩、珊瑚礁台、悬崖海岸、环礁潟湖。悬崖岸没有拍岸浪与泡沫线，水面只是正常地和岩壁相交；礁台外缘可以加一圈 -5 m 的礁坪，让水柱逐渐变浅。

俯视能看清岸线的分层：浅水从沙色过渡到青绿，泡沫贴在水线附近，浪谷不会把海床露出来。

3. 岸线的两套新开关（默认关闭）

2.0 做了两件事解决「深水区到浅水区突然变小」和「陡坡处浪谷露底」：

  • shoreSensing：长浪读约 140 m 的粗平滑水深，中浪混合，细浪读本地；陡坡处不再沿一条等深线折出阶梯。
  • shoreHandoff：破碎点之后让 FFT 的长中浪快速退场、拍岸浪接管，细浪保留 55%；浅水用邻域最大海床夹紧，冲浪带整体增水。

但这两项会明显改变岸线观感，所以 2.0 的默认值是 0（旧岸线行为）。想要新岸线，把面板「岸线交班」「岸线分层」拉回 1 就能做 A/B，不用改代码。下面这组对比是礁台上的岸线感知关闭 / 打开：

4. 浮力：从固定弹簧到质量驱动

1.0 的船是一组固定刚度 / 阻尼的弹簧。2.0 改成由质量派生：三种船只预设（轻型小艇 / 中型帆船 / 重型货船），每个预设给你一整套上升 / 下落刚度、阻尼、最大倾角和重心高度，也能单独微调。

浮力探针可视化也换了画法：每个采样点是一个绿色圆球贴在水面，上面两根黄色箭头。箭头方向不是固定的——每帧用 GPU 水面查询回来的真实波高，在采样点周围 1.4 m 求一次法线，再把箭头转过去，所以浪推过来时箭头会跟着翻。

二、API 上，和 1.0 差在哪

项 1.0 2.0
波浪后端 三段级联 128² 四层级联 256²（600 / 85 / 12 / 2.1 m）
地形 固定潟湖岛 terrain: 'sand' | 'reef' | 'cliff' | 'atoll' | 'open'，切换重建
波浪参数 wind / wavelength / choppiness 新增 fetchKm、waveScale、spreadBlend、swellScale、swellDirection、timeScale、layerWeight1..3、coverageScale
岸线 nearshoreDamping + 岸线泡沫带 新增 shoreHandoff、shoreSensing、reefShelf、windwardBoost、reefImpactFoam、surfCoupling
海岸细节 — terrainDetail、reefShelf
船体 / 浮力 固定弹簧参数 boatPreset、boatMass、buoyancyRiseStiffness、buoyancyFallStiffness、buoyancyRiseDamping、buoyancyFallDamping、buoyancyMaxTilt、buoyancyCog、buoyancyStep、buoyancyProbes
天空 9 套预设，HDRI 或体积云 新增 sky（跟随环境预设 / 指定 HDRI）、physicalLighting；HDRI 之间 1 s 交叉淡入
声音 无 ambience、ambienceVolume，四轨环境音随海况与水下状态切换
方法 update / setMode / getSettings … 新增 getMode()、applySettings()、resize()、isUnderwater
事件 progress / ready / error / stats / weather / change 新增 mode、destroyed
画质档位 折射 0.5 / 0.7 / 1.0 / 1.0 0.4 / 0.6 / 0.75 / 1.0；Low 直接跳过平面反射
旧参数 峰顶阈值 / 峰顶衰减 / 泡沫流速 / 各向异性 X-Y / 高光曲率 … 这些属于 1.0 的旧着色器，2.0 由 Ultra 光谱和 Jacobian 白沫接管，不再单独暴露

另外，2.0 末期移除了 island 开关和 GLTF 小岛的高度场：地形完全由 terrain 决定，库用户仍可以用 overlays 自己叠岛。island.glb 现在只作为沙滩棕榈树的模型源保留，不再出现在场景里。

三、性能：2.0 删掉的浪费

2.0 一帧最多有三次场景绘制：折射缓冲（不含水面与天空）、半分辨率平面反射、主画面。这一轮把重复开销压掉了：

  • 阴影贴图每帧只重画一次。以前折射 / 反射 / 主画面每调一次 render() 都会重画 2048² 的阴影图，现在三遍共用。
  • 平面反射隔帧更新，Low 画质直接跳过；开阔海地形没有露出水面的部分，也不再进反射通道。
  • 焦散隔帧生成。水面到海床的光斑有 512² + 256² 两套，30 Hz 看不出差别。
  • HDRI 天空下不再空跑体积云。选择 HDRI 预设时体积云网格是隐藏的，但以前仍然每帧跑全屏 raymarch、云阴影和立方体更新，结果没有任何地方采样。
  • 场景矩阵每帧只遍历一次，折射缓冲不再绘制背景。

想再快，优先降 pixelRatio 和 quality；quality: 'Low' 会同时降网格段数、反射尺寸、折射缓冲和 FFT 分辨率。

两个注意点：

  • assetBase 必须保持相对路径 ./assets/，改成绝对路径在子目录部署会 404。
  • 资源约 45 MB，建议静态服务开 gzip / brotli；HDRI 与 takram 的天空 LUT 占大头。

五、踩过的坑

  1. HDRI 天空下，体积云一直在后台跑。 sky.visible = false 只是不画网格，atmosphere.update() 仍然每帧执行 raymarch 和立方体面更新。加上可见性判断之后，这一整块开销直接归零——这也是 2.0 帧数提升最明显的一处。
  2. 一次帧里三次 render()，阴影就重画三次。 shadowMap.autoUpdate = true 是跟着每个 render() 走的，不是跟着帧走的。改成手动 needsUpdate 后要记得每帧在第一次 render 之前设置。
  3. 关了 scene.matrixWorldAutoUpdate 必须手动 updateMatrixWorld(true)。 根节点的 matrixWorldNeedsUpdate 是 false 时，普通调用不会继续遍历子节点，船和浮标会停在原地。
  4. 新岸线默认是关的。 shoreHandoff / shoreSensing 默认 0，所以 2.0 刚打开时岸线看起来和 1.0 是一套；想要分层感知和交班，得把面板两个滑杆拉回 1。
  5. 小岛高度场会让海床在岛的轮廓上出现一圈断崖。 模型的地面网格在边缘直接结束，没有水下裙边，合并到地形后就是十几米的竖直落差，水面会在那里被浅水逻辑压平。2.0 最终的取舍是移除小岛，库层面保留 overlays 给需要的人。
  6. 浮力箭头要跟真实波高，不能用 CPU 的近似波。 GPU 查询点追加在列表末尾，前面浮标 / 尾流探针 / 鲨鱼的固定下标才不会错位。

最后

1.0 是把海做出来，2.0 是把海放进一个能走、能潜、能换地貌的场景里，并且把每帧真正花时间的地方摊开看清楚。如果你只想要一片能嵌页面的海，1.0 的 API 依然兼容；如果你要海岸、要地形、要船真的跟着浪起伏，2.0 是现在这一版。

在线体验（已覆盖 1.0）：https://xiangjianhuan-blog.github.io/water-demo/
